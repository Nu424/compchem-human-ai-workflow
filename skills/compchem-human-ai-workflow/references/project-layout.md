# フォルダ構成と記録

目標：「いつ、何をして、何が得られ、それは今も信用してよいか」が、フォルダと README だけで分かること。

## 構成

研究テーマ単位で git 管理し、使い回すスクリプトと、1 回ごとの試行を分ける。

```text
<テーマ>/                              例: pt-h-adsorption/（git で管理）
  README.md                           目的、現時点の結論、試行の一覧（状態付き）
  <スキル用フォルダ>/compchem-human-ai-workflow/  この skill（.claude/skills/、.agents/skills/ など。エージェントによる）
  scripts/                            使い回すスクリプト（pipeline_*.py、recipes.py、job.slurm を同じ場所に置く）
  trials/
    <YYMMDD>_<何をしたか>/             1 回の試行 = 1 つの計画
      README.md                       目的・計画の要約・結果・結論・状態
      plan.yaml                       この試行の計画
      local/                          この試行だけの特殊なスクリプト（必要なときだけ）
      runs/<系>/<段階>/               計算の入出力（git 管理外）
      results/                        集計結果、results.db、確認カード、図
      logs/                           Slurm の出力
  analyses/
    <YYMMDD>_<何を調べたか>/           複数の試行を横断する解析
      README.md                       使った試行と、分かったこと
  notes/                              学習メモ（learning.md）
```

- 試行のフォルダ名は `<YYMMDD>_<内容を表す短い英語>`。日付は試行を始めた日。
- 1 つの計画で収まらないほど内容が変わったら、新しい試行にする。
- 大きな生データ（WAVECAR、CHGCAR、軌跡など）は `.gitignore` に入れる。クラスタ側にしかない場合は、その場所を試行の README に書く。

## スクリプトの使い回し

- 共通スクリプトは `scripts/` に置き、試行フォルダを引数で受け取る：`python scripts/pipeline_vasp.py run trials/261020_energy-checks o2`。
- 試行に固有の値（系、条件、資源）は、スクリプトではなく試行の `plan.yaml` に書く。
- テンプレートの `provenance()` が git のコミットを結果に記録する。過去の試行は、そのコミットのスクリプトで再現できる。
- 改造が必要になったら：
  - 他の試行でも役立つ改造 → `scripts/` を直してコミットする。
  - その試行だけの事情 → `local/` にコピーして改造し、試行の README に理由を書く。
- git を使わない場合は、使ったスクリプトを試行フォルダにコピーしておく。

## 状態

試行の README の先頭と、テーマの README の索引に、同じ状態を書く。

| 状態 | 意味 |
|---|---|
| `計画中` | 計画レビュー前、または OK 待ち |
| `実行中` | 投入済み |
| `完了` | 計算は終わったが、結論はまだ |
| `採用` | 結論前の確認が済み、結論に使ってよい |
| `探索` | 結論には使わない軽い試し |
| `置き換え済み（→ <試行名>）` | 新しい試行で置き換えた。古い結果は参照しない |
| `棄却（<理由>）` | 誤り、または目的に合わないと判断した |

- 棄却しても**消さない**。理由を書いて残す。「なぜ棄却したか」は後で役に立つ知見になる。
- 結論や図に使ってよいのは `採用` の試行だけ、とテーマの README に明記する。

## 結果と図

- 図は `results/` か `analyses/` のスクリプトからだけ作る。手作業で作った図を残さない。
- 図ごとに、元になった試行・計算・スクリプトを、同じ名前の `.md`（例：`adsorption.png` と `adsorption.md`）か、解析フォルダの README に書く。
- 結果の表には、状態（`妥当` `要確認` `未収束` `除外`）を必ず添える（review-points.md）。

## 試行の README

`templates/trial_README.md` を使う。最低限、状態、目的、計画の要約、実行したコマンド、結果の要約、結論、残った疑問を書く。実行の詳細な記録は、結果ファイル（`result.json` の provenance）と Slurm の出力に任せる。
